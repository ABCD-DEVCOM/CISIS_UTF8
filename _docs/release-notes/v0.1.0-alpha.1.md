# XisCore Engine v0.1.0-alpha.1 (test release)

> **This is a test release.** It is published so that the people who run ABCD can try the new engine in one place and report what they find. **Do not replace the binaries of a production ABCD with it.** Try it on a copy of ABCD and on copies of your databases.

## What this is

XisCore Engine is the ABCD Community's continuation of **CISIS 5.7e**, the C library and command-line programs created by BIREME/PAHO to read, write, index and search CDS/ISIS databases. It is the engine under ABCD: `wxis` serves ABCD's web pages, `mx` and about 35 smaller programs do the rest (import, export, indexing, conversion).

Until now ABCD has shipped binaries that were built years ago (CISIS 5.2bb from 2007 on Windows, 5.7e from 2014–2015 on Linux, UTF-8 builds from 2016–2019) and that nobody could rebuild in the same way. This release is the first one built **from source, with scripts that anyone can run again**, for Linux and Windows, ANSI and UTF-8. The banner says `XisCore Engine v0.1.0`; the file formats and the command-line behaviour are those of CISIS.

Both packages have the same layout as ABCD's `cgi-bin`:

| Folder | Variant | Character set | Used by ABCD for |
|---|---|---|---|
| `cgi-bin/ansi/` | `isis1660` | ANSI (ISO-8859-1) | administrative databases (`acces`, `loanobjects`, `reserve`, `copies`, `servers`, `suggestion`, `trans`) |
| `cgi-bin/ansi/bigisis/` | `bigisis` | ANSI | large databases |
| `cgi-bin/utf8/` | `isis1660` | UTF-8 | the same, UTF-8 installations |
| `cgi-bin/utf8/bigisis/` | `bigisis` | UTF-8 | the same, UTF-8 installations |

Every folder has `mx`, `wxis` and the other programs (38 on Windows and 39 on Linux in the ANSI folders; two fewer in UTF-8, see Known issues). `wxis1660` and `wxisnonuni` are copies kept because ABCD's `cgi-bin` has files with those names. Each package also has `INSTALL.txt` and `BUILDINFO.txt` (the commit it was built from, the banners and the SHA-256 of every file).

## What changed compared with the binaries ABCD ships today

- **Built from this repository** with `build_all.sh` (Linux) and `build_windows_all_bcc55.bat` (Windows), which build all 14 CISIS variants, or exactly the ABCD set, always as **two separate engines: ANSI and UTF-8**.
- **UTF-8**: case folding, word splitting, truncated searches and the `uctab=`/`actab=` tables work on UTF-8 text. Russian, Hebrew and accented Latin text index and search correctly.
- **64-bit Linux** behaves like 32-bit: addresses were stored in `int` in the format language compiler (any format crashed in a modern 64-bit executable), and several copies between overlapping memory corrupted text.
- **Defects fixed**, on every platform:
  - the end-of-dictionary marker on Linux cut UTF-8 keys out of `ifkeys` and of truncated searches;
  - `ifkeys from=/to=` crashed;
  - accented characters inside format comments (`/* ação */`) read outside a table;
  - the format and search parsers read one byte before their buffers;
  - in some 64-bit builds the LIND index posting type was unsigned, which broke searches.
- **Documentation**: [`_docs/LIMITS.md`](https://github.com/ABCD-DEVCOM/CISIS_UTF8/blob/master/_docs/LIMITS.md) gives the measured limits of every variant (record size, key length, number of records, file size) and which variant can read which database. [`_docs/COMPILING.md`](https://github.com/ABCD-DEVCOM/CISIS_UTF8/blob/master/_docs/COMPILING.md) explains how to build and what was verified.

## Tested, and not tested

Tested:

- Linux 64-bit: every program of the ABCD set builds; every `mx` creates, indexes and searches a database (`build_all.sh -T`); the UTF-8 and ANSI test suites pass (`smoke_test.sh`, `smoke_test_ansi.sh`).
- Linux: 758 real ABCD print formats give the same output in 32 and 64 bit; the core programs run clean under AddressSanitizer.
- Limits and cross-variant compatibility were measured on Linux (`_docs/LIMITS.md`).

**Not tested yet** (this is what the test release is for):

- The Windows binaries inside ABCD. The ANSI Windows builds were compiled for the first time for this release.
- Reading and writing ABCD's existing databases with these binaries in place of the old ones (CISIS 5.2bb on Windows, 5.7e on Linux). The banners match field by field, but byte-for-byte compatibility has not been checked.
- Most of the smaller programs: they build and start, but their results are not checked by a test.

## How to try it

1. Make a backup copy of ABCD's `cgi-bin` folder and of the databases you will test with.
2. Copy the contents of the package's `cgi-bin/` over ABCD's `cgi-bin`.
3. Run `mx` from the folder and check the first line: `XisCore Engine v0.1.0/...`.
4. Work on copies of your databases: open them, search, browse, edit and save records, rebuild an index, import and export.
5. To go back, restore the backup of step 1.

A database must be read and written by a binary of the same variant (`isis1660` or `bigisis`). Do not mix ANSI and UTF-8 binaries on the same database: accented characters get corrupted.

To check a download: `sha256sum -c SHA256SUMS.txt` (Linux) or `Get-FileHash <file> -Algorithm SHA256` (Windows PowerShell).

## Known issues

- `mxgw` and `mz` are not built in UTF-8 (they still split words byte by byte); use the ANSI ones.
- `sizeof2` is a gcc-only diagnostic program and is not built on Windows.
- The `512G` in the banner of the large-file Linux builds is a fixed string; the real master-file limits are in `_docs/LIMITS.md`.
- There is no 64-bit Windows build yet; the 32-bit `.exe` files run on 64-bit Windows.

## Reporting a problem

Open an issue at https://github.com/ABCD-DEVCOM/CISIS_UTF8/issues with:

- the first line printed by `mx` (the banner);
- the operating system, and whether it is the ANSI or the UTF-8 folder;
- what you did (the command, or the ABCD page and action), what you expected and what happened;
- if possible, a small database or record that shows the problem (without personal data).
